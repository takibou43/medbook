# الحضور والمناوبات والطابور وحجوزات الضيوف

## السلوك

- الأولوية حسب وقت الموعد بين الحاضرين؛ يمكن إدخال صاحب موعد لاحق مبكرًا عند غياب من قبله. وصول صاحب موعد أسبق قبل التأكيد يعيد ترتيب الأولوية، وبعد الإدخال لا يُستبدل المريض الجاري.
- يبدأ الطبيب والمساعد المناوبة يدويًا بوقت نهاية اليوم. تنتهي صلاحية المناوبة تلقائيًا في الخادم دون إنهاء الاستشارة أو حذف الحضور. فتح التطبيق لا يبدأ المناوبة.
- عند وجود مساعد نشط ضمن نطاق الطبيب، نداء التالي ينشئ طلبًا معلقًا دون اسم مريض أو إدخال. المساعد يسجّل الحضور مستقلًا ثم يؤكد أول حاضر. الطبيب يتولى الاستقبال فقط عند غياب مساعد في المناوبة، ويشمل التحقق المساعد المشترك للعيادة.
- طلب الاستعجال لمريض حاضر يتطلب سببًا وموافقة الطبيب. يُقدَّم بعد الاستشارة الحالية دون قطعها.
- يستطيع الطبيب حجز موعد جديد لضيف بالاسم واللقب والهاتف وبرمجة متابعة مرتبطة بموعده السابق، دون إنشاء حساب وهمي.
- ربط الحجوزات القديمة يبدأ برمز هاتف صالح لعشر دقائق، محدود المحاولات والإرسال، محفوظ كبصمة HMAC. بعد التحقق تؤكد العيادة هوية المريض شخصيًا لكل سجل مطابق ضمن نطاق الطبيب. لا ربط تلقائي بالاسم أو الرقم، ولا دمج لسجلات أفراد العائلة أو حساب آخر.
- تذكير الخمس دقائق يتحقق من المداومة؛ الإشعارات المعتادة للحسابات والمتابعات العائلية محفوظة. رسائل التحقق تعتمد إعداد BudgetSMS الموجود ولا تُرسل أثناء الاختبارات.

## قاعدة البيانات والرجوع

ثلاثة ترحيلات إضافية: حقول المناوبة/طلب النداء، حقول الاستعجال، وجدول guest_identity_claims. لا حذف بيانات أو تغيير كلمات مرور أو أدوار أو اشتراكات. جُرّبت ملفات SQL الثلاثة على قاعدة PostgreSQL محلية جديدة من مخطط main؛ migrate diff أظهر عدم وجود فرق مع المخطط الجديد. تشغيل Render الحالي يزامن المخطط بواسطة db push ثم يبدأ Node بشرط نجاح المزامنة.

عند الرجوع تُعاد نسخة التطبيق السابقة ويُحتفظ بالأعمدة والجدول الإضافيين؛ لا حذف سجلات التحقق أو المواعيد كجزء من الرجوع.

## التحقق

- نجحت TypeScript وبناء الواجهتين محليًا؛ نجحت الواجهتان في CI على Node 22.
- نجحت اختبارات الحضور والاستعجال والهوية وحجوزات الضيوف، وعدّاد النداء والأمن.
- اجتازت 71 حالة مركزة تشمل PostgreSQL محليًا. اختبار العيادات يرفض اسم قاعدة attendance_test بحارسه، ولذلك يُعاد ضمن قاعدة security_test المعتمدة، دون تعديل الحارس.
- الفحص الكامل على PostgreSQL وCI جارٍ قبل الدمج؛ لا تُعد هذه الوثيقة إثبات نشر إنتاج حتى يُسجل SHA وحالة Render وVercel والفحص الحي.
- لم تُرسل رسائل SMS أو إشعارات حقيقية للاختبار، ولم تُعدّل بيانات الإنتاج أثناء التطوير.
