# المرحلة الثانية: لغة الوصفة والطباعة

2026-10-10 — عمل محلي فقط على fix/prescription-phase1-20261010، فوق إصلاحات المرحلة الأولى غير المنشورة.

## 1. نتائج الفحص
- ثبت أن PrescriptionSheet يستخدم getLanguage وt وformatDayAr المرتبطة بلغة اللوحة. لهذا لم تكن لغة الوصفة مستقلة.
- في Clinic توجد nameAr وaddress فقط؛ وفي Doctor توجد firstName وlastName وaddress دون بدائل فرنسية. Specialty وWilaya لهما nameFr اختياري؛ لم تُضف حقول مفترضة إلى API.
- لم يثبت خطأ ترجمة داخل أسماء البيانات؛ بقاؤها بالعربية كان نتيجة الحقول الأصلية المتاحة. لم تُترجم أسماء المرضى أو النصوص المدخلة آليًا.
- كان تجميع الدواء وتعليماته موجودًا عبر break-inside:avoid. تم الحفاظ عليه، مع تحسين قواعد العنوان والتفاصيل والملاحظات.

- frontend-doctor/src/lib/prescription.ts: لغة طباعة وبيانات مهنية اختيارية بحسب اللغة ضمن المسودة في الذاكرة؛ تُحتسب البيانات المهنية المكتوبة محتوى لمنع فقدها عند تغير الزيارة.
- frontend-doctor/src/components/prescription/PrescriptionCard.tsx: اختيار لغة الطباعة داخل المحرر وحقول اختيارية لاسم الطبيب والعيادة والعنوان خاصة باللغة المختارة، دون حفظ ملف مهني.
- frontend-doctor/src/components/prescription/PrescriptionPrint.tsx: الورقة تعتمد لغة المسودة وحدها للعنوان والتاريخ والتسميات والتوقيع والختم؛ النصوص والأسماء معزولة الاتجاه بواسطة bdi وtranslate=no.

- frontend-doctor/src/i18n/fr.json: نصوص واجهة الإعدادات الجديدة بالفرنسية.
- frontend-doctor/tests/prescriptionPrint.test.ts (جديد): تاريخ وتسميات اللغتين، الرجوع إلى البيانات الأصلية، الحفاظ على المستفيد والمحتوى عند تغيير اللغة والبيانات المهنية.
- docs/prescription-phase2/: تقرير ومعاينة HTML مستقلة من المكوّن الفعلي وأداة توليدها وصور الاختبار.

## 3. قبل وبعد
قبل: تغيير لغة اللوحة هو ما يغير تسميات الورقة؛ اسم العيادة والعنوان يعرضان الأصل فقط. الآن: لغة مستقلة داخل المسودة، مع بيانات مهنية اختيارية لكل لغة. تُستخدم البيانات الأصلية عند ترك الحقول فارغة. الاسم المعتمد للمريض لا يتغير.
تظل الوصفة معاينة وطباعة فقط، دون حفظ أو إرسال أو تغيير موعد. لا استدعاءات API جديدة ولا تعديل صلاحيات أو اشتراكات أو مخطط قاعدة البيانات.
ورقة المعاينة A4 بعرض 210mm وارتفاع أدنى 297mm؛ الهوامش 16mm أعلى و15mm جانبيًا و14mm أسفل تطابق @page. لا ضمان لبقاء كتلة أطول من صفحة كاملة دون تقسيم؛ هذه حدود طبيعية للطباعة.

## 6. اقتراح البيانات المهنية الدائمة والأعمال المنفصلة
الحل الحالي لا يحتاج migration: بيانات اختيارية في المسودة الحالية لكل لغة، تُحذف عند الخروج أو مسح المسودة وفق سلوكها المحلي. لا تمثل تحديثًا للملف المهني ولا تحفظًا للوصفة.
إذا طُلب حفظ بيانات فرنسية دائمة لاحقًا: اقتراح nullable fields للعيادة nameFr وaddressFr، وللطبيب firstNameFr وlastNameFr وaddressFr، مع الإبقاء على الحقول العربية/الأصلية. يلزم تعديل مخطط Prisma وmigration وواجهات التحقق وDTO/API ونماذج الملف المهني، وتمكين التعديل وفق الصلاحيات الحالية فقط (الطبيب لنفسه ومسؤول العيادة لعيادته)، واختبارات الرجوع للأصل وعزل العيادات. لا backfill آلي ولا ترجمة أسماء ولا تغيير بيانات إنتاج دون إذن. هذا اقتراح غير منفذ ويحتاج موافقة منفصلة.
A5 قد يناسب وصفة قصيرة بدواء أو دواءين، لكن الأسماء والملاحظات الطويلة ستزيد الصفحات؛ بقي A4 وحده دون توسيع نطاق هذه المرحلة.
لم تبدأ المرحلتان الثالثة والرابعة. لا push ولا deploy ولا رسائل حقيقية ولا تعديل بيانات إنتاج.
