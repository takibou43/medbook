# مراجعة المرحلة الأولى — إدارة MedBook

العمل محلي فقط على الفرع `fix/admin-phase1-20261008` داخل `admin-phase1-20261008`، انطلاقًا من المرجع المحلي `origin/main` عند `a842a90`. لم تتغير ملفات المصدر الموجودة في `current-release`، ولم ينفذ push أو merge أو deploy أو migration أو اتصال بقاعدة إنتاج.

## التغييرات

- أصبحت هوية المستلم تُجلب بمعرف الطبيب باستعلام مستقل عن بحث المحادثات. يبقى اسمه وتخصصه عند ظهور «لا نتائج مطابقة»، ويُحجب محرر الإرسال إذا لم يمكن تحديده مع زر إعادة محاولة.
- المسودات ومحاولة الإرسال مرتبطة بمعرف الطبيب داخل جلسة الصفحة. يحفظ الفشل النص ومفتاح منع التكرار، وتحتفظ العودة إلى الطبيب بمسودته. يُمسح النص بعد نجاح الطلب فقط، مع حارس فوري ضد النقر المتكرر. لا تحفظ المسودات في التخزين الدائم أو عبر إعادة تحميل الصفحة.
- نتائج البحث وروابط النشاط تفتح قوائم مقيدة بمعرف الطبيب أو حساب المريض أو الموعد. تدعم المسارات الخلفية معرف UUID وتبقى تحت حماية ADMIN الحالية.
- تحفظ قوائم المواعيد والأطباء والمستخدمين والبحث العام البحث والفلاتر والصفحة في URL لاستعادة الحالة عند الرجوع أو إعادة التحميل. الاستعلامات تفصل نتائج البحث وتلغي الطلب القديم في القوائم والبحث العام.
- بطاقة العيادات تفتح قسم العيادات. تُعرض هوية فرد العائلة في الموعد ونتيجة البحث قبل اسم صاحب الحساب، مع إرجاع `familyMemberId` وعلاقة فرد العائلة من الخادم.
- أضيفت أسماء وتلميحات حذف التخصص والبلدية والتقييم. أصبح التقييم صورة دلالية باسم «4 من 5» ونص مرئي، بدل أزرار نجوم معطلة.
- ارتبط البريد في إعدادات الحساب بـ label ومعرف حقيقي وautocomplete واتجاه LTR. أضيفت تسميات بحث وفلاتر الإدارة، واسم الولاية في عنوان إضافة البلدية، ونص «إضافة بلدية».
- تاريخ النشاط ووقت حدوثه أصبحا مميزين عن تاريخ الموعد، وتاريخ مكافأة العيادة يُعرض بصيغة عربية بدل قص ISO.
- ثُبت تحميل نسخة React واحدة في Vite للنسخة المعزولة ذات الاعتماديات المرتبطة، وأصبح لها مخبأ منفصل.

## الملفات المعنية

- `backend/src/modules/admin/admin.routes.ts` و`admin.service.ts`: فلاتر المعرف وروابط النشاط وحقول المستفيد وuserId لنتائج المرضى.
- `backend/tests/adminDeepLinks.routes.test.ts`: حماية وفلاتر HTTP وحقول المستفيد.
- `frontend-doctor/src/hooks/useAdminListParams.ts`: حفظ حالة القوائم في الرابط.
- `frontend-doctor/src/pages/admin/`: الرسائل والرئيسية والمواعيد والأطباء والمستخدمون والعيادات والمحظورون والتخصصات والولايات والتقييمات.
- `frontend-doctor/src/pages/AccountSettings.tsx`، `components/messages/ChatPane.tsx`، `components/ui/RatingStars.tsx` و`Modal.tsx`.
- `frontend-doctor/vite.config.ts` و`.gitignore`: إعداد المعاينة المعزولة فقط.

## التحقق وحدوده

- فحص الأنواع وبناء الواجهة وبناء الخادم: نجحت بعد تثبيت اعتماديات محلية وتوليد عميل Prisma فقط؛ لم يشغّل أي migration أو db push.
- اختبارات الواجهة الحالية: 65 نجحت.
- اختبارات HTTP ومنطق المراسلة والأمن ذات الصلة: 59 نجحت في 4 ملفات، منها 11 اختبارًا جديدًا للروابط. Prisma وهمي، بلا بيانات حقيقية أو إرسال خارجي.
- اختبارات المتصفح: 17 رحلة نجحت، بلا أخطاء JavaScript، بما فيها انقطاع الشبكة والطلبات المتأخرة وTab/Shift+Tab. نتائج المتصفح التفصيلية: [browser-results.json](browser-results.json). شغلت الواجهة الحقيقية ببيانات API وهمية مع حجب جميع الوجهات الخارجية. صور قبل/بعد في [screenshots](screenshots).
- شملت الرحلات هوية المستلم أثناء التصفية، عزل المسودات، فشل الإرسال وإعادة المحاولة ومفتاح منع التكرار، الربط بالمعرف، الدخول المباشر/reload/back/forward، حفظ البحث والترقيم، فرد العائلة، التقييم العددي، label البريد، Escape وإعادة التركيز، وعروض 360 و390 و768 و1280.
- لم يُثبت تسليم رسالة حقيقية أو صلاحيات عبر PostgreSQL حقيقي. لم تختبر تعديلات الاشتراك والتوثيق والحظر والمكافآت والكتالوج والحماية الكاملة لآخر مدير في هذه المرحلة؛ حالتها في مصفوفة الأفعال منفصلة.
- لم تستخدم قارئ شاشة فعليًا أو لوحة مفاتيح هاتف افتراضية؛ التحقق الحالي للأسماء الدلالية وTab/Escape والتركيز وقياسات العرض.
- لم تتكرر مشكلة URL المواعيد مع محتوى الرئيسية في الرحلات المحلية المختبرة؛ لا ينسب لها سبب مفترض.
- العبارة «جراحة العضام و المفاصل» غير موجودة في المصدر المعتمد بهذه النسخة. الكتالوج يحتوي «جراحة العظام والرضوض»؛ لم تغير أسماء أو معرفات أو علاقات ولم تزامن الإنتاج. تصحيح سجل حي بعينه يحتاج تحديده وتصريح بيانات مستقل.
- بقية توحيد التصميم وبطاقات الجداول على الهاتف وتحسينات الأقسام محفوظة للمرحلتين الثانية والثالثة حسب المرفق.

## الحفاظ على البيانات والقواعد

لا تغيير في مخطط Prisma أو الحجوزات أو الطابور أو عمليات حالة الموعد أو الأدوار أو ملفات الحساب أو الصلاحيات أو الأسعار أو قواعد الاشتراك أو مكافآت الإحالة. التغييرات الخلفية استعلامات قراءة فقط. لم تنفذ أفعال إدارة حقيقية. تعديل `ChatPane` مشترك مع واجهة الطبيب؛ بناء الواجهة واختبارات المراسلة ناجحة، واختبارات الطبيب الحالية لم تتغير.

## المعاينة المحلية

[افتح المعاينة](http://127.0.0.1:5188/login)، ثم استخدم حساب البيانات الوهمية `admin@example.test` وكلمة المرور الوهمية `demo-only-1234`. الخادم المحلي يقبل الدخول الوهمي ولا يتصل بنظام المصادقة الحقيقي.

لتشغيلها لاحقًا من جذر النسخة المعزولة في نافذتين:

```powershell
node docs/admin-phase1/preview/fixture-api.cjs
```

```powershell
$env:VITE_API_URL='http://127.0.0.1:4181/api'
npm --prefix frontend-doctor run dev -- --host 127.0.0.1 --port 5188
```

اختبارات المتصفح في `preview/browser-test.cjs` تستخدم Chromium الموجود محليًا؛ مساره محدد في السكربت وقد يلزم تحديثه على جهاز آخر. العمليات غير المدعومة في خادم المعاينة تعيد خطأ واضحًا، ولا تدعي حفظًا حقيقيًا.
