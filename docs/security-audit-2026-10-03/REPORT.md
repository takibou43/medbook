# تدقيق وإصلاح أمني — 3 أكتوبر 2026

## النتائج والإصلاحات

1. **اقتطاع كلمات المرور الطويلة (متوسطة، مثبتة محليًا):** bcrypt يقبل كلمتين لهما أول 72 بايتًا نفسها. التسجيل يقبل حتى 128 خانة، والعربية متعددة البايتات. اختبار إعادة الإنتاج يثبت قبول لاحقة مختلفة في التجزئة القديمة، ويرفضها بعد الإصلاح. الكلمات الجديدة فوق 72 بايتًا تستخدم SHA-384 مع فصل نطاق وBase64 (64 حرفًا) ثم bcrypt بكلفة 10 وبادئة إصدار واضحة. الكلمات القصيرة والتجزئات القديمة تبقى متوافقة. طول كلمات المرور الجديدة محدود بـ128 خانة في دالة الحفظ نفسها، والمقارنة محدودة بـ4096 خانة.
   - **قيد مهم:** التجزئات القديمة لا تحتوي اللاحقة المقتطعة، فلا يمكن استرجاعها أو إصلاحها آليًا بأمان. الحسابات التي استعملت كلمات طويلة قديمًا تحتاج تغيير كلمة المرور بعد النشر. لم تُغيّر كلمات مرور أي مستخدم.
2. **كشف الحسابات في دخول الأطباء (منخفضة إلى متوسطة):** الحساب غير الموجود كان يُرفض قبل bcrypt، والحساب المعطل يعيد 403 حتى مع كلمة مرور خاطئة. أصبح المسار يقارن تجزئة وهمية للحساب الغائب ويعيد 401 للحساب المعطل مع كلمة خاطئة؛ 403 يبقى بعد التحقق من كلمة المرور فقط. الاختبارات تثبت تنفيذ المقارنة وتماثل رموز الرفض؛ لم يُنفذ قياس إحصائي للتوقيت في الإنتاج.
3. **غياب منع التخزين المؤقت لردود API (تحصين خصوصية):** أضيف Cache-Control: no-store لكل /api قبل CORS والمصادقة. اختبارات HTTP تشمل رد خروج ناجح و401. الفحص الحي أكد غياب الترويسة في المسارات المفحوصة قبل النشر؛ لم يثبت وجود بيانات طبية في مخزن وسيط. هذا لا يغيّر التخزين الصريح المنفصل للمواعيد في واجهة العمل دون اتصال.
4. **رفض CORS يعيد 500 (خلل معالجة، وليس تجاوز صلاحيات):** رفض الموقع غير المسموح أصبح 403 بدل خطأ خادم. الاختبار يؤكد غياب Access-Control-Allow-Origin وعدم استدعاء إبطال الجلسة.
