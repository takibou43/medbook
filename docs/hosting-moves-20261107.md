# نقل الاستضافة والنسخ الاحتياطي — خطة 2026-11-07

## 1) من Vercel إلى Cloudflare Pages (قبل أول اشتراك مدفوع)

خطة Vercel Hobby للاستعمال غير التجاري فقط، والتجربة المجانية للأطباء تنتهي في 2026-12-31.

**جاهز في المستودع:** `frontend/public/_headers` و`frontend-doctor/public/_headers` مولَّدة من `vercel.json`
(`node scripts/cloudflare-pages-headers.mjs`، وCI يتحقق من تطابقها). لا حاجة إلى `_redirects`:
Cloudflare Pages يعامل الموقع كتطبيق صفحة واحدة ما دام لا يوجد `404.html`.

**خطوات المالك (حساب Cloudflare مجاني، بلا بطاقة):**
1. Workers & Pages → Create → Pages → Connect to Git → `takibou43/medbook`.
2. مشروع المرضى: Root directory `frontend`، Build command `npm run build`، Output `dist`،
   ومتغيرات `VITE_API_URL=https://medbook-xg66.onrender.com/api` و`NODE_VERSION=22`.
3. مشروع الأطباء: الإعدادات نفسها مع Root directory `frontend-doctor`.
4. في Render أضف الرابطين الجديدين (`https://<project>.pages.dev`) إلى `CLIENT_URL` مع إبقاء روابط Vercel.
5. جرّب الحجز وتسجيل الدخول والإشعارات على الرابطين الجديدين، ثم انشرهما.
6. بعد أسبوعين بلا مشاكل: احذف روابط Vercel من `CLIENT_URL` وأوقف مشروعَي Vercel.

ملاحظة: اشتراكات Web Push مرتبطة بأصل الموقع؛ المرضى والأطباء يفعّلون الإشعارات مرة أخرى على الرابط الجديد.

## 2) تقريب الخادم وقاعدة البيانات من الجزائر (فرانكفورت) — خطة فقط

الحالي: Render في `oregon` وNeon في `aws-us-east-2`.
- منطقة خدمة Render لا تتغير: يلزم إنشاء خدمة جديدة في Frankfurt بالإعدادات والمتغيرات نفسها، ثم تبديل `VITE_API_URL` وCSP.
- منطقة مشروع Neon لا تتغير: يلزم مشروع جديد في `aws-eu-central-1` ونقل البيانات (`pg_dump`/`pg_restore`)
  في نافذة صيانة، ثم تبديل `DATABASE_URL`.
- **لم يُنفَّذ شيء:** نقل بيانات المرضى تغيير إنتاجي يحتاج موافقة صريحة ونافذة صيانة ونسخة احتياطية.
- القانون 18-07 يقيّد نقل البيانات الشخصية (والصحية خاصة) إلى الخارج. فرانكفورت، مثل أمريكا،
  خارج الجزائر؛ يُستشار مختص أو السلطة الوطنية لحماية المعطيات (ANPDP) قبل الإطلاق التجاري.
