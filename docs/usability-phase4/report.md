# المرحلة الرابعة: التحقق وسهولة الاستخدام

ثبت أن الخادم يرفض أصلًا سنوات الخبرة السالبة والكسور؛ النقص كان في الواجهة. أضيف min=0 وstep=1 وتحقق React Hook Form ورسالة مرفقة بالحقل. لا حد أعلى اعتباطي. استخرج مخطط الخادم كما هو إلى doctorProfile.schema.ts لاختباره مباشرة.

الهاتف صار tel/inputmode=tel/LTR وtranslate=no دون تطبيع أو تعديل الأرقام المخزنة. الأسماء والأدوية محمية عند الملاءمة من ترجمة المتصفح.

ثبت اختلاف تعريف العدد: النظرة العامة كانت تجمع الحساب وفرد العائلة تحت patientId، والقائمة تستخدم patientId+familyMemberId. صارت البطاقة تستخدم نفس المفتاح مع استمرار قاعدة تجميع الضيوف القائمة دون حذف أو دمج بيانات. أضيف شرح لنطاق العدد.

وسعت أهداف تغيير المريض والحذف وإعادة ترتيب الجلسات واختيار الوقت إلى 44px. حصر Tab وEscape صار للنافذة العليا فقط؛ تستبعد التفاصيل المطوية والعناصر المخفية.

## التحقق
- اختبارات الواجهة: 84/84 ناجحة.
- اختبارات الخادم المستهدفة: 20/20، تشمل -5 و1.5 والصفر وحساب أفراد العائلة والضيوف.
- في المتصفح الفعلي مع API وهمي: -5 و1.5 منعَا الحفظ بلا طلب؛ الصفر أرسل طلبًا وهميًا بالقيمة الصحيحة.
- نافذتان متداخلتان: Escape يغلق العليا فقط ويعيد التركيز؛ Tab من summary المطوي يعود إلى زر الإغلاق، لا إلى الصفحة.
- عرض390px دون تجاوز أفقي؛ الصورة mobile.jpg.
- فحوص البناء الكاملة وCI مدونة في تقرير الإصدار لاحقًا.

## الحدود
لا تغييرات schema أو migrations أو أدوار أو اشتراكات؛ لا اختبارات تغير بيانات الإنتاج. إصدار PDF/طباعة مادية لم يُتحقق منه. الملفات المهنية الفرنسية اختيارية للمسودة فقط؛ اقتراح حقول دائمة يتطلب موافقة مستقلة.
