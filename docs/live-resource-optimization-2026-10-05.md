# تحسين الموارد مع الحفاظ على المزايا

## التغييرات

- إشارة تحديث مباشرة عبر طلب انتظار يصل إلى25ثانية، بهيدر المصادقة الحالي وتجديد الجلسة الحالي، دون إرسال التوكن في الرابط. يتحقق الخادم من تفعيل الحساب ونطاق الأطباء في كل طلب. إشارات المواعيد خاصة بالأطباء المعنيين ومساعديهم؛ لا تحتوي أسماء أو هواتف أو معرفات أو بيانات طبية. التغييرات الإدارية غير المحددة تبطل النطاقات كلها احتياطيًا.
- عند اتصال الإشارة تصبح قراءات الطابور والمواعيد والدخل ولوحة الطبيب كل60ثانية احتياطيًا، وتحدث فور الإشارة أو الإجراء المحلي. عند تعطل الإشارة تعود الفترات الأصلية10ثوانٍ للطبيب و4ثوانٍ للمساعد و15/30ثانية للقوائم والإحصاءات. يتوقف طلب الانتظار عند إخفاء الصفحة أو الخروج؛ العودة تحدث البيانات لتعويض الأحداث الفائتة.
- ضغط gzip بالمستوى1 لردود GET الكبيرة الخاصة بقوائم العيادة، مع إبقاء Cache-Control:no-store. لا تضغط مسارات كلمات المرور أو الرموز أو الدعوات.
- مشاركة قراءات الطابور المتزامنة بعد التحقق من صلاحيات كل طالب، بمفتاح الطبيب/اليوم/نسخة التحديث؛ لا يحتفظ الخادم بالنتائج بعد انتهاء القراءة ولا يستخدم نتائج سابقة للتعديل.
- التذكيرات تبقى على الوتيرة الأصلية قرب المواعيد ولمن ينتظرون الآن وللتذكيرات المستحقة، ويتراجع الفحص حتى15دقيقة عندما لا توجد مهام قريبة؛ الحجز أو تعديل الموعد يوقظ المهمة فورًا. بقي الحجز الذري وقواعد عدم التكرار وإعادة التحقق قبل الإرسال كما هي.
- مزامنة الاشتراكات عند التغييرات ووقت أقرب انتهاء، مع فحص احتياطي15دقيقة. بقيت قواعد منح التجربة والتعطيل اليدوي كما هي. مهام الغياب وتنظيف الإشعارات ونافذة إبقاء Render مستيقظًا كما هي.
- لا تغييرات على Prisma أو بيانات الإنتاج أو familyMemberId أو أدوار الحسابات أو واجهات API الحالية.

## التحقق والقياس

- بناء TypeScript للخادم وبناء بوابة الأطباء نجحا؛63اختبارًا لواجهة الأطباء.
- قبل تحسين عزل الإشارات نجحت541حالة خادم محلية؛ بعد العزل نجحت23حالة متأثرة إضافية. CI سيفحص النسخة النهائية كاملة علىNode22 وPostgreSQL مؤقت.
- اختبارات جديدة تغطي المصادقة وتعطيل الحساب، الأحداث الفائتة وانتظار التحديث، عزل الأطباء، عدم البث عند فشل الحجز، حماية no-store والتوافق مع العملاء دون gzip، استقلال بيانات الأطباء، فشل القراءة وإعادة المحاولة، التذكيرات المستحقة وعدم تداخل مهام الخلفية.
- npm audit --omit=dev: صفر ثغرات لاعتماديات التشغيل في وقت الفحص.
- قائمة اختبار اصطناعية83موعدًا:32678بايت خام→1614بايتgzip، خفض95%. هذا قياس اصطناعي وليس قياس بيانات الإنتاج.
- مع6لوحات مفتوحة8ساعات: الطلبات الدورية للموظفين50,400→11,520، بالإضافة إلى نحو6,912طلب انتظار صغير. الخفض في حالة الهدوء نحو63% بعد احتساب الإشارة. تضاف قراءات عند التغييرات؛ لذا لا نعد بخفض63% في يوم عمل فعلي ولا90% من جميع موارد المشروع.
- تتلقى الواجهة إشارة ثم تجلب القائمة الحالية المصرح بها؛ لا يتضمن هذا الإصدار بروتوكول فروق صفوف المواعيد. الضغط وتقليل تكرار القوائم هما توفير النقل الحالي.
- تشغيل نسخة API واحدة علىRender مناسب لهذا البث داخل العملية. التوسع إلى عدة نسخ يحتاج ناقل أحداث مشترك؛ فحص60ثانية يبقى شبكة أمان، وليس ضمان تحديث فوري بين نسخ متعددة.

تحسن فرصة البقاء ضمن حصصNeon وRender، لكن لا ضمان شهر مجاني قبل قياس الإنتاج؛ ملفات المرضى والتحديثات الفعلية وساعات النشاط تحدد النتيجة. Vercel Hobby يبقى مقيدًا بالاستخدام الشخصي غير التجاري.
